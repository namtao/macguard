## Details

<a id="filevault"></a>

### `filevault`: FileVault disk encryption

- **Severity:** high
- **Area:** System
- **What it does:** Requires your password to unlock the startup disk after every restart. On Apple silicon it also protects the firmware, so the Mac cannot boot another disk, open Recovery or be revived in DFU mode without authorization.
- **How to fix (manual):** System Settings > Privacy & Security > FileVault > Turn On, then store the recovery key safely.
- **Risk if you do not fix it:** Someone who takes the Mac can read your files after a restart without knowing your password.
- **Risk when you fix it:** If you forget the login password and lose the recovery key, the data cannot be recovered. Store the recovery key somewhere safe.
- **Source:** drduh macOS Security and Privacy Guide

<a id="sip"></a>

### `sip`: System Integrity Protection (SIP)

- **Severity:** high
- **Area:** System
- **What it does:** Stops any process, even one running as root, from modifying protected system files, services and processes.
- **How to fix (manual):** Only possible from Recovery: shut down, hold the power button, choose Options, open Utilities > Terminal, run 'csrutil enable' and restart.
- **Risk if you do not fix it:** Malware that gets administrator rights can modify macOS itself and hide inside system services.
- **Risk when you fix it:** Tools that need to modify or trace the system, such as DTrace, stop working.
- **Source:** drduh macOS Security and Privacy Guide

<a id="gatekeeper"></a>

### `gatekeeper`: Gatekeeper checks downloaded apps

- **Severity:** high
- **Area:** System
- **What it does:** Verifies the signature and Apple notarization of apps before they open for the first time.
- **Command `macguard fix` runs:**

```bash
sudo spctl --global-enable
```

- **If the automatic fix fails:** Run 'sudo spctl --global-enable', or allow apps from the App Store and identified developers in System Settings > Privacy & Security.
- **Risk if you do not fix it:** Unsigned or tampered apps, a common way to spread malware, open without any warning.
- **Risk when you fix it:** You are warned before opening apps that are not notarized. You can still allow one in Privacy & Security.
- **Source:** drduh macOS Security and Privacy Guide

<a id="firmware"></a>

### `firmware`: Startup security set to Full Security

- **Severity:** high
- **Area:** System
- **What it does:** Only the current, Apple-signed macOS can boot. This is the default.
- **How to fix (manual):** Start up in Recovery, open Utilities > Startup Security Utility, select the startup disk and choose Full Security.
- **Risk if you do not fix it:** An older, vulnerable or modified operating system and third-party kernel extensions can be loaded.
- **Risk when you fix it:** Third-party kernel extensions and older macOS versions will no longer boot or load.
- **Source:** drduh macOS Security and Privacy Guide

<a id="updates"></a>

### `updates`: Automatic security updates

- **Severity:** high
- **Area:** System
- **What it does:** Turns on automatic checks, downloads, security responses, system data files (XProtect) and macOS updates. The guide asks to keep the system up to date; requiring automatic installation of macOS updates is macguard's stricter reading of that advice.
- **Command `macguard fix` runs:**

```bash
for key in AutomaticCheckEnabled AutomaticDownload CriticalUpdateInstall ConfigDataInstall AutomaticallyInstallMacOSUpdates; do
  sudo defaults write /Library/Preferences/com.apple.SoftwareUpdate "$key" -bool true
done
```

- **If the automatic fix fails:** System Settings > General > Software Update > Automatic Updates: turn every option on.
- **Risk if you do not fix it:** The Mac stays exposed to known vulnerabilities, including ones already exploited in the wild.
- **Risk when you fix it:** macOS may restart by itself to finish an update, so save your work. Rarely, an update breaks an app.
- **Source:** drduh macOS Security and Privacy Guide

<a id="autologin"></a>

### `autologin`: Automatic login is off

- **Severity:** high
- **Area:** Accounts and login
- **What it does:** Makes the Mac ask for a password at the login window after every restart.
- **Command `macguard fix` runs:**

```bash
sudo sysadminctl -autologin off
```

- **If the automatic fix fails:** System Settings > Users & Groups > Automatically log in as: Off.
- **Risk if you do not fix it:** Anyone who powers on the Mac gets straight into your account. Automatic login also stores your password in a weakly protected file (/etc/kcpassword).
- **Risk when you fix it:** You type your password after each restart. Unattended machines that must come back on their own after a power cut will wait at the login window.
- **Source:** Not in the guide; common hardening added by macguard

<a id="firewall"></a>

### `firewall`: Application firewall is on

- **Severity:** high
- **Area:** Network and firewall
- **What it does:** Controls which apps may accept incoming network connections. It does not filter outgoing traffic.
- **Command `macguard fix` runs:**

```bash
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --setglobalstate on
sudo pkill -HUP socketfilterfw
```

- **If the automatic fix fails:** System Settings > Network > Firewall: On.
- **Risk if you do not fix it:** Any app or service listening on a port can be reached by every device on the same network.
- **Risk when you fix it:** macOS asks the first time a new app wants to accept incoming connections. Malware with admin rights can still turn the firewall off.
- **Source:** drduh macOS Security and Privacy Guide

<a id="pending_updates"></a>

### `pending_updates`: No pending software updates

- **Severity:** medium
- **Area:** System
- **What it does:** Confirms that the updates macOS already found have been installed. Uses the result of the last background scan, without contacting Apple.
- **How to fix (manual):** System Settings > General > Software Update > Update Now, or run 'softwareupdate --list' then 'sudo softwareupdate --install --all'.
- **Risk if you do not fix it:** Security fixes that are already downloaded or available stay uninstalled.
- **Risk when you fix it:** Installing may require a restart and, rarely, breaks an app.
- **Source:** drduh macOS Security and Privacy Guide

<a id="xprotect"></a>

### `xprotect`: XProtect malware signatures are recent

- **Severity:** medium
- **Area:** System
- **What it does:** XProtect is the antivirus built into macOS. It detects and removes known malware using signatures that Apple updates in the background.
- **Command `macguard fix` runs:**

```bash
sudo xprotect update
```

- **If the automatic fix fails:** Run 'sudo xprotect update' and keep automatic security updates on.
- **Risk if you do not fix it:** New malware families released since the last update are not detected.
- **Risk when you fix it:** None known. The update downloads data from Apple.
- **Source:** drduh macOS Security and Privacy Guide

<a id="backup"></a>

### `backup`: Encrypted Time Machine backup

- **Severity:** medium
- **Area:** System
- **What it does:** Keeps restorable copies of your data, encrypted so a lost or stolen backup disk does not expose it. The guide recommends the 3-2-1 model: three copies, two kinds of media, one off-site.
- **How to fix (manual):** System Settings > General > Time Machine > Add Backup Disk, and tick Encrypt Backup.
- **Risk if you do not fix it:** Ransomware, a disk failure or theft can destroy your data for good. An unencrypted backup disk exposes everything on it.
- **Risk when you fix it:** Losing the backup password makes the encrypted backup unreadable. If you back up with another tool, you can ignore this item.
- **Source:** drduh macOS Security and Privacy Guide

<a id="screenlock"></a>

### `screenlock`: Password required immediately after sleep or screen saver

- **Severity:** medium
- **Area:** Accounts and login
- **What it does:** Locks the session as soon as the screen saver starts or the display sleeps. The guide sets this with 'defaults write com.apple.screensaver askForPassword'; current macOS no longer reads those keys, so macguard uses sysadminctl, which sets the same option as System Settings.
- **Command `macguard fix` runs:**

```bash
sysadminctl -screenLock immediate -password -
```

- **If the automatic fix fails:** System Settings > Lock Screen > Require password after screen saver begins or display is turned off: Immediately.
- **Risk if you do not fix it:** During the delay, anyone near the Mac can use your unlocked session.
- **Risk when you fix it:** You type your password (or use Touch ID) every time the screen wakes. The command asks for your login password.
- **Source:** drduh macOS Security and Privacy Guide

<a id="guest"></a>

### `guest`: Guest account is off

- **Severity:** medium
- **Area:** Accounts and login
- **What it does:** Removes the passwordless Guest user from the login window.
- **Command `macguard fix` runs:**

```bash
sudo sysadminctl -guestAccount off
```

- **If the automatic fix fails:** System Settings > Users & Groups > Guest User > Allow guests to log in: Off.
- **Risk if you do not fix it:** Anyone can log in without a password and use the Mac, its network and its shared folders.

- **Source:** Not in the guide; common hardening added by macguard

<a id="stealth"></a>

### `stealth`: Firewall stealth mode

- **Severity:** medium
- **Area:** Network and firewall
- **What it does:** The Mac stops answering probes, pings and connection attempts on closed ports.
- **Command `macguard fix` runs:**

```bash
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --setstealthmode on
sudo pkill -HUP socketfilterfw
```

- **If the automatic fix fails:** System Settings > Network > Firewall > Options > Enable stealth mode.
- **Risk if you do not fix it:** Network scanners easily find the Mac and pick it as a target.
- **Risk when you fix it:** Other devices cannot ping the Mac, which can confuse network troubleshooting.
- **Source:** drduh macOS Security and Privacy Guide

<a id="certs"></a>

### `certs`: No custom certificate trust settings

- **Severity:** medium
- **Area:** Network and firewall
- **What it does:** Looks for certificates that a user, admin, VPN, security product or MDM has marked as trusted beyond the Apple root store.
- **How to fix (manual):** Open Keychain Access, check the login, Local Items and System keychains, and set any certificate you do not recognise to Never Trust.
- **Risk if you do not fix it:** An unexpected trusted certificate lets whoever holds its key silently intercept your HTTPS traffic.
- **Risk when you fix it:** Removing trust from a certificate you do need (company network, VPN, debugging proxy) breaks those connections.
- **Source:** drduh macOS Security and Privacy Guide

<a id="ssh"></a>

### `ssh`: Remote Login (SSH server) is off

- **Severity:** medium
- **Area:** Sharing and open ports
- **What it does:** Turns off the SSH server, which is off by default on macOS.
- **Command `macguard fix` runs:**

```bash
sudo systemsetup -f -setremotelogin off || {
  sudo launchctl disable system/com.openssh.sshd
  sudo launchctl bootout system/com.openssh.sshd
}
```

- **If the automatic fix fails:** System Settings > General > Sharing > Remote Login: Off.
- **Risk if you do not fix it:** Anyone who can reach port 22 can try to log in, for example by guessing passwords.
- **Risk when you fix it:** You can no longer connect to this Mac with ssh, scp or rsync over SSH. If you need SSH, keep it on and pass the ssh_password item instead.
- **Source:** drduh macOS Security and Privacy Guide

<a id="ssh_password"></a>

### `ssh_password`: SSH server accepts keys only, not passwords

- **Severity:** medium
- **Area:** Sharing and open ports
- **What it does:** When Remote Login is on, refuses password and keyboard-interactive logins so only SSH keys work. Written to a separate file and validated with 'sshd -t'.
- **Command `macguard fix` runs:**

```bash
printf 'PasswordAuthentication no\nKbdInteractiveAuthentication no\n' | sudo tee /etc/ssh/sshd_config.d/000-macguard.conf >/dev/null
sudo sshd -t || sudo rm -f /etc/ssh/sshd_config.d/000-macguard.conf
```

- **If the automatic fix fails:** Add 'PasswordAuthentication no' and 'KbdInteractiveAuthentication no' to a file in /etc/ssh/sshd_config.d/, then run 'sudo sshd -t'.
- **Risk if you do not fix it:** Attackers who reach port 22 can guess or reuse your password to get a shell.
- **Risk when you fix it:** If your public key is not in ~/.ssh/authorized_keys yet, you lock yourself out of SSH. Undo by deleting /etc/ssh/sshd_config.d/000-macguard.conf.
- **Source:** drduh macOS Security and Privacy Guide

<a id="listeners"></a>

### `listeners`: No other service listens on the network

- **Severity:** medium
- **Area:** Sharing and open ports
- **What it does:** Lists every process accepting TCP connections on an address other than localhost. Without sudo only your own processes are visible.
- **How to fix (manual):** For each service listed: bind it to 127.0.0.1 if only this Mac needs it, otherwise stop it. rapportd is Handoff (see the handoff item).
- **Risk if you do not fix it:** Each open service is a way in. Development servers and databases bound to all interfaces are often reachable by anyone on the network.
- **Risk when you fix it:** Binding a service to 127.0.0.1 or stopping it makes it unreachable from other devices, including your own phone or VPN.
- **Source:** drduh macOS Security and Privacy Guide

<a id="sudo_password"></a>

### `sudo_password`: sudo always asks for a password

- **Severity:** medium
- **Area:** Accounts and login
- **What it does:** Looks for NOPASSWD rules in /etc/sudoers and /etc/sudoers.d, which let commands run as root without typing a password.
- **How to fix (manual):** Run 'sudo visudo' (and 'sudo visudo -f' for each file in /etc/sudoers.d) and remove or narrow the NOPASSWD rules listed.
- **Risk if you do not fix it:** Any program running as you, including malware, can become root silently.
- **Risk when you fix it:** Scripts or tools that relied on password-less sudo will stop and ask for a password.
- **Source:** Not in the guide; common hardening added by macguard

<a id="ssh_key_passphrase"></a>

### `ssh_key_passphrase`: SSH private keys are protected by a passphrase

- **Severity:** medium
- **Area:** Accounts and login
- **What it does:** Checks every private key in ~/.ssh. Keys on a hardware token (sk-...) count as protected.
- **How to fix (manual):** For each key listed, run 'ssh-keygen -p -f ~/.ssh/<key>' and set a passphrase.
- **Risk if you do not fix it:** Anyone who copies the key file, for example from a backup or through malware, can log in to every server that trusts it.
- **Risk when you fix it:** You type the passphrase when the key is used. Add it to the macOS keychain with 'ssh-add --apple-use-keychain' to avoid typing it every time.
- **Source:** drduh macOS Security and Privacy Guide

<a id="ssh_host_keys"></a>

### `ssh_host_keys`: SSH verifies server host keys

- **Severity:** medium
- **Area:** Accounts and login
- **What it does:** Looks for 'StrictHostKeyChecking no' or 'UserKnownHostsFile /dev/null' in ~/.ssh/config and /etc/ssh/ssh_config, which turn off server verification.
- **How to fix (manual):** Remove those lines, or limit them to a specific test host instead of 'Host *'.
- **Risk if you do not fix it:** Someone on the network can impersonate a server and capture what you send, including passwords and code.
- **Risk when you fix it:** SSH asks you to confirm a server's key the first time you connect, and warns if it later changes.
- **Source:** drduh macOS Security and Privacy Guide

- **What it does:** Keeps administrator rights in a separate account, so programs you run day to day cannot make system-wide changes with your credentials.

- **Source:** drduh macOS Security and Privacy Guide

<a id="hostname"></a>

### `hostname`: Computer name does not identify you

- **Severity:** low
- **Area:** Accounts and login
- **What it does:** The computer name is broadcast to local networks by sharing and discovery services.
- **Command `macguard fix` runs:**

```bash
printf "New computer name (e.g. MacBook) / Tên máy mới: "
read -r new_name
[ -n "$new_name" ] || return 1
host_name=$(printf %s "$new_name" | tr -cs 'A-Za-z0-9-' '-' | sed 's/^-*//; s/-*$//')
sudo scutil --set ComputerName "$new_name"
sudo scutil --set HostName "$host_name"
sudo scutil --set LocalHostName "$host_name"
```

- **If the automatic fix fails:** System Settings > General > About > Name, or run 'sudo scutil --set ComputerName <name>' (also HostName and LocalHostName).
- **Risk if you do not fix it:** Anyone on the same network (café, hotel, office) can see your name or username.
- **Risk when you fix it:** Devices that know this Mac by its old name (SSH configs, shared folders, AirDrop contacts) see a new name.
- **Source:** drduh macOS Security and Privacy Guide

<a id="sudo_home"></a>

### `sudo_home`: sudo does not keep your HOME

- **Severity:** low
- **Area:** Accounts and login
- **What it does:** macOS keeps HOME when you use sudo, so programs running as root read configuration files from your home folder. This removes HOME from env_keep using a separate, validated file in /etc/sudoers.d.
- **Command `macguard fix` runs:**

```bash
rule_file=$(mktemp)
echo 'Defaults env_keep -= "HOME"' > "$rule_file"
sudo visudo -cf "$rule_file" && sudo install -m 0440 -o root -g wheel "$rule_file" /etc/sudoers.d/macguard-env-home
rm -f "$rule_file"
```

- **If the automatic fix fails:** Run 'sudo visudo -f /etc/sudoers.d/macguard-env-home' and add the line: Defaults env_keep -= "HOME"
- **Risk if you do not fix it:** A program that can write to your home folder can plant configuration that root later loads.
- **Risk when you fix it:** Commands run with sudo use root's home (/var/root), so your personal tool settings no longer apply under sudo. Undo by deleting /etc/sudoers.d/macguard-env-home.
- **Source:** drduh macOS Security and Privacy Guide

<a id="signed"></a>

### `signed`: Firewall asks before allowing signed apps

- **Severity:** low
- **Area:** Network and firewall
- **What it does:** By default the firewall silently allows incoming connections to software signed by Apple or an identified developer. This makes macOS ask first.
- **Command `macguard fix` runs:**

```bash
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --setallowsigned off
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --setallowsignedapp off
sudo pkill -HUP socketfilterfw
```

- **If the automatic fix fails:** System Settings > Network > Firewall > Options: turn off automatically allowing built-in and downloaded signed software.
- **Risk if you do not fix it:** Any signed app, including a signed but malicious one, can accept connections without you knowing.
- **Risk when you fix it:** You get more prompts. AirDrop stops working until you allow rapportd and sharingd (see 'macguard tips').
- **Source:** drduh macOS Security and Privacy Guide

<a id="dns"></a>

### `dns`: Encrypted or filtering DNS

- **Severity:** low
- **Area:** Network and firewall
- **What it does:** Encrypts DNS lookups with a DNS profile (Quad9, AdGuard, NextDNS) or a local resolver such as dnscrypt-proxy or dnsmasq.
- **How to fix (manual):** Install a DNS profile from Quad9, AdGuard or NextDNS, or 'brew install dnscrypt-proxy' and point DNS to 127.0.0.1.
- **Risk if you do not fix it:** Your network provider and anyone on the network can see, log or alter every domain you visit.
- **Risk when you fix it:** The DNS provider now sees your lookups. Some VPNs and captive portals override or conflict with custom DNS.
- **Source:** drduh macOS Security and Privacy Guide

<a id="wifi"></a>

### `wifi`: Wi-Fi uses WPA3

- **Severity:** low
- **Area:** Network and firewall
- **What it does:** WPA3 protects the Wi-Fi password against offline guessing and encrypts traffic better than WPA2.
- **How to fix (manual):** Set the router to WPA3 Personal (or WPA2/WPA3), and turn on Private Wi-Fi Address for each network in System Settings > Wi-Fi > Details.
- **Risk if you do not fix it:** Someone nearby can capture the handshake and try to crack the Wi-Fi password.
- **Risk when you fix it:** Older devices that only support WPA2 cannot join a WPA3-only network.
- **Source:** drduh macOS Security and Privacy Guide

<a id="bonjour"></a>

- **Severity:** low
- **Area:** Network and firewall
- **What it does:** Stops the Mac from announcing itself and its services to the local network with multicast DNS.

<a id="brew_redirect"></a>

### `brew_redirect`: Homebrew refuses HTTPS to HTTP redirects

- **Severity:** low
- **Area:** Software
- **What it does:** Sets HOMEBREW_NO_INSECURE_REDIRECT=1 in ~/.zprofile so downloads cannot be downgraded from HTTPS to HTTP.
- **Command `macguard fix` runs:**

```bash
sh -c 'grep -qx "export HOMEBREW_NO_INSECURE_REDIRECT=1" ~/.zprofile 2>/dev/null || echo "export HOMEBREW_NO_INSECURE_REDIRECT=1" >> ~/.zprofile'
```

- **If the automatic fix fails:** Add 'export HOMEBREW_NO_INSECURE_REDIRECT=1' to your shell startup file.

<a id="ssh_key_strength"></a>

### `ssh_key_strength`: SSH keys use strong algorithms

- **Severity:** low
- **Area:** Accounts and login
- **What it does:** Flags DSA keys and RSA keys shorter than 3072 bits. Ed25519, ECDSA and hardware-token keys pass.
- **How to fix (manual):** Create a new key with 'ssh-keygen -t ed25519', add it to your servers and services, then remove the old key.
- **Risk if you do not fix it:** Weak keys are easier to break and are being refused by more and more servers.
- **Risk when you fix it:** A new key must be added to every server and service that trusts the old one before the old key is removed.
- **Source:** Not in the guide; common hardening added by macguard

<a id="ssh_agent_forwarding"></a>

### `ssh_agent_forwarding`: SSH agent forwarding is off

- **Severity:** low
- **Area:** Accounts and login
- **What it does:** Looks for 'ForwardAgent yes' in ~/.ssh/config and /etc/ssh/ssh_config.
- **How to fix (manual):** Remove 'ForwardAgent yes', or allow it only for a specific trusted host.
- **Risk if you do not fix it:** An administrator or attacker on a server you connect to can use your keys to log in elsewhere as you while the session is open.
- **Risk when you fix it:** Hopping from one server to another with your local keys stops working. Use 'ssh -J' (ProxyJump) instead, which does not expose the agent.
- **Source:** Not in the guide; common hardening added by macguard
